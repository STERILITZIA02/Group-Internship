# Sprint workflow

## Select work

Keep the backlog in [main-repository issues](https://github.com/STERILITZIA02/Group-Internship/issues). Leave the milestone open until the team selects the work. Before starting, agree on an owner, an observable acceptance check and the target repository (`area:main`, `area:demo-3d` or `area:demo-platform`). Split work that can be delivered and checked independently into sub-issues.

Use [Sprint planning](https://github.com/users/STERILITZIA02/projects/2/views/2) to check the work selected for each milestone. The [Sprint Plan](https://github.com/STERILITZIA02/Group-Internship/wiki/Sprint-Plan#sprint-schedule) holds the five sprint goals.

## Deliver and review

On the [delivery board](https://github.com/users/STERILITZIA02/projects/2/views/1), pick up a Todo item and move it to In Progress. If blocked, add `blocked` and record the dependency and next action. Move to In Review when a teammate can inspect the result. Run the issue's acceptance check and attach the evidence to the issue or linked PR. Close the issue after the accepted change reaches the main project. For demo changes, follow the [submodule handover](../CONTRIBUTING.md).

For an agent handoff, add `agent-ready` once the issue identifies the starting files, scope and acceptance check. Hand back the PR or commit, checks run and any work still open.

## Feedback and sprint close

Use the **User feedback** issue form for observations from user sessions. During Sprint 3, take a reproducible quick fix into the current milestone and retest it. Move a challenge that needs investigation into Sprint 4 with the original scenario, evidence and a check for improvement.

At the sprint review, demonstrate the outcome against the goal. Return unfinished issues to the backlog or select a later milestone. Record the demo link, feedback and one improvement in the sprint review issue. Link that record from the [weekly statement](https://github.com/STERILITZIA02/Group-Internship/wiki/Weekly-Work-Statements).
